# 变更记录

## 0.3.0 - 2026-10-07

- **破坏性变更（触发条件）**：结束前的检查改由 todo 列表驱动，与 OMP 的 `todo.checkCompletion` 对齐。判定分两层——**是否介入**看本任务有没有用 todo 列表跟踪过（出现过含任务的快照），**是否强制续跑**看是否仍有 pending/in_progress 项。没有用过 todo 的任务（含只改了几个文件的简单任务）结束时不写报告、不提示、不续跑，即使修改过文件或声明过验收计划；旧的"任何文件修改都触发"不再提供开关。
- todo 全部完成或被清空后不再强制续跑，但仍会登记最终结论（证据齐备记 `evidence_complete`，缺失记 `unverified` 并说明原因是 todo 已无未完成项），避免状态停在中间态而看不到结论。
- 新增 `src/todo.ts`：按 rpiv-todo 自己的 `state/replay.ts` 规则判定 `details`（`tasks` 数组 + 数字 `nextId`），`pending`/`in_progress` 计入未完成，`completed`/`deleted` 墓碑不计入。快照按用户任务累积和重置，只调用过空列表不算用过 todo，同一会话里上一个任务不会让下一个任务被检查。
- 续跑提示中加入未完成 todo 的数量与条目，`/auto-verify status` 增加"触发条件"一行，便于判断本次为什么不介入、为什么不续跑或为什么续跑。
- `src/verify.md` 说明触发条件，并要求把验证本身放进 todo 列表、证据记录完成后再标记完成。
- `settle` 增加可选的不可续跑原因参数，使"todo 已无未完成项"不再显示成误导性的"当前会话不能继续运行"。
- 验收协议本身未变：逐项清单、修复前后对照、视觉证据、审查缓存与上限、超时上限、取消和项目信任检查保持原有行为。

## 0.2.0 - 2026-10-06

- 根据 OMP 的 Verify、Delivery、session_stop 和可选 Advisor 流程补强，新增源码对照文档。
- 新增 `verify_plan`，逐项验收标准只能补充；运行证据必须绑定具体标准。
- 新增缺陷修复前真实失败记录与修复后成功对照；缺失复现必须明确说明。
- Web/桌面标准必须有工具真实返回的图像及运行证据，纯文字不能充当视觉验收。
- 新增可选 `verify_review`，独立文本上下文审查实际工具输出与原始任务，缓存同代次结论并限制调用次数。
- 区分证据齐备和审查通过，限制代码任务通过“不适用”跳过验证，补充会话切换时旧结果隔离。
- 工具接口变更：`verify_run`、`verify_evidence` 必须提供验收编号 `criteria`；启用后先由代理调用 `verify_plan`。未保留 0.1.0 的单一 smoke 槽位放行方式。

## 0.1.0 - 2026-10-06

- 新增 OMP 风格的自主冒烟/E2E 验证规则和结束前自动续跑。
- 新增实际命令执行、已有工具证据引用及受阻/不适用报告。
- 新增修改后证据失效、有限续跑、取消和项目受信任检查。
